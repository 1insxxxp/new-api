# Public group display pricing

The version-2 sync contract optionally includes `source_group_id`, `source_model`, and `source_group_ratio` on inherited category models. All three are required together. Ordinary legacy version-1 payloads remain accepted; inherited source fields require version 2. Every snapshot version must match its envelope. Sub emits version 2 globally so an old version-1 receiver rejects the payload safely after rollback. Category entry `group_ratio` is 1. Source prices are raw USD per token or per request, already resolved by Sub (including its selected context tier and aliases).

New multiplies each provided price by `source_group_ratio` exactly once and saves it in `PublicGroupDisplayPricing`. Missing prices stay absent; explicit zero stays zero. Input, output, image input/output, and cache prices remain independent, including zero input with paid output. This is a display quote, not a new New billing policy. The response adds `group_pricing[group_name]` to the existing single model row. Neither this option nor these fields are read by relay/billing code.

`PublicGroupSyncBillingModels` records ordinary-sync model ownership. Inherited models do not participate in global model price/ratio/billing-mode precedence, writes, or deletion. Normal snapshot behavior is preserved. Deploy the updated receiver/UI before enabling source category exports; old receivers reject version 2 instead of ignoring the source fields and corrupting global prices.

## Ordinary group display quotes

Version-2 snapshots may also carry an optional `display_pricing` map, keyed by the exact public model name and using the existing model-pricing DTO. Ordinary `model_pricing` payloads retain their existing wire and billing semantics, and their snapshot `group_ratio` need not be 1. The new map never participates in channel type selection, model mapping, global billing options, billing precedence, or `PublicGroupSyncBillingModels` ownership.

Each explicit quote requires the full source triple: `source_group_id` must equal the snapshot's `group_id`, `source_model` must equal its map key, and `source_group_ratio` must be present. The model must belong to `models`. `billing_mode` must be `token`, `per_request`, `image`, or `video` (case and surrounding whitespace are normalized). All provided prices and the source ratio must be finite and nonnegative, including the multiplied result. An explicit quote cannot overlap an inherited `model_pricing` entry carrying source fields. All entries, including those on disabled snapshots, are validated before any channel or option write; an invalid entry rejects the whole envelope. Existing inherited-category rules, including category `group_ratio == 1`, are unchanged.

Prices are raw USD/token or USD/request **before** `source_group_ratio`. The receiver uses the existing `displayPrice()` conversion exactly once and persists the result only in `PublicGroupDisplayPricing`. For example, an ordinary image group can retain billing `group_ratio: 1.5` while its display quote has `per_request_price: 0.2` and an independent `source_group_ratio: 1`, yielding $0.20; a source ratio of 1.5 yields $0.30. Sub resolves the effective source quote, including token/context units and image-rate policy, before sending it. Missing price pointers stay absent and explicit zero remains zero.

The overlay is replaced on each complete sync. Omitting a quote removes the previous quote; omitted, null, or empty `display_pricing` maps remain accepted on both version-1 and version-2 ordinary snapshots and clear previous explicit quotes. `GET /api/pricing` exposes the effective quote through existing `group_pricing` fields without changing stored billing ratios or the shared pricing cache. No frontend change is needed for this receiver addition. Deploy this receiver before enabling the producer's new map: older version-2 receivers silently ignore the unknown field, so version 2 alone does not establish support for ordinary display quotes.

The response retains configured group ratios, including logged-in users' group-specific overrides, even when only some models have display quotes. Models without a quote continue to use those ratios for ordinary display pricing. The existing frontend quote path ignores the response multiplier for effective `group_pricing` values, so quotes are not multiplied twice. Category snapshots still store `group_ratio: 1`; inherited quotes remain effective independently of a user's response ratio. This response-only behavior does not change any stored billing or routing state.

## Hide stale plaza channels while retaining routes

Set `PUBLIC_GROUP_SYNC_HIDDEN_CHANNEL_IDS=20` (or a comma-separated list of positive IDs) on the New application. Only GET `/api/pricing` applies this configuration. An association is omitted only when it is supplied by selected channels and no other visible channel supplies the same `(group, model)` association. Groups exclusively exposed by selected channels are removed from this response's selector, ratio, ordering and auto-group fields. Shared models/groups remain visible through other channels. Invalid IDs produce an error response rather than silently hiding a different scope.

No channel, ability, key, token, group permission, billing option, `/v1/models` response, or shared pricing cache is changed. Removing the environment setting reverses the exclusion. Do not remove the legacy group from `UserUsableGroups` or `GroupRatio`: token authentication still requires those entries.

For the audited production state, channel 20 has real credentials for Sub custom group 260; matching model routes target source 71 rather than source 128. Channel 47 is a placeholder mirror. Token 7 retains its legacy group; channel 20 accepts 12 prefixed model names. Do not retag, rename, delete, or migrate these resources as part of this display fix.
